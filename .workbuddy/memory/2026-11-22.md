## v3.3.3 crates.io 发布历程（5 轮 CI 修出来的门禁清单）

- 仓库发版走 tag 触发的 Release workflow：Verify（fmt/clippy `--all-features -D warnings`/workspace tests 含 doctest/rustdoc `-D warnings`/rustsec audit-check/cargo-deny）→ 三平台 build → publish（cargo publish 到 crates.io，需 repo secret `CARGO_TOKEN`）→ Create GitHub Release。crates.io 上的 3.3.2/3.3.3 之前没发是因为 workflow 一直挂在 Verify。
- 门禁坑（本地必须全复现）：① clippy 要跑 `--all-features`（sgx/legacy_ws 等 feature 门控代码本地默认不编译）；② doctest 在 CI 是 warnings-denied（`no_run` 示例也要零警告零错误，未使用变量/多余 mut 都会挂）；③ rustdoc 有 `rustdoc::bare_urls`（裸 URL 要加尖括号）；④ **audit-check 读 `.cargo/audit.toml` 的 ignore，cargo-deny 读根目录 `deny.toml`——两份 ignore 要同步维护**；⑤ cargo-deny 的 advisory DB 更新后会暴露新公告（chrono unmaintained、crypto-bigint timing、quinn 系列等，逐个升级或带理由 ignore）。
- 本地 advisory DB 拉取被 github HTTPS 干扰挡住：把 `~/.cargo/advisory-dbs/advisory-db-*` 的 origin 换成 SSH URL 即可（一次性改，cargo-deny 继续用）。
- workflow 的 `dtolnay/rust-toolchain@stable` 已全量钉到 `@1.99.1`（rust-toolchain.toml 钉版本后 @stable 装的工具链与 target std 不匹配，导致 macOS E0463）；build-test.yml 的 MSRV job 也 1.95.0→1.99.1。
