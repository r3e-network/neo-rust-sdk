## Executive Summary

The v3.3.0 release represents a significant hardening of the Neo Rust SDK's security infrastructure, primarily focused on completing the SGX quote verification system that was foundationalized in v3.2.0. This release addresses critical production readiness gaps identified during extensive fuzz testing and HD wallet regression analysis conducted in Q3 2026. The primary engineering objective is to transition from experimental security components to production-grade verification pipelines capable of detecting tampered enclave attestations, certificate revocations, and replay attacks in enterprise deployment scenarios.

Concurrently, this release tackles systemic API inconsistencies discovered through property-based testing campaigns. Fuzz testing generated over 1,000 edge-case inputs that exposed silent failures in address/script-hash conversions and multisig script hash computation paths. Rather than patching individual symptoms, v3.3.0 adopts a systematic refactoring approach: introducing fallible conversion APIs with explicit error handling, adding comprehensive test coverage, then deprecating unsafe convenience methods while maintaining backward compatibility through transitional wrappers.

## Version Bump Justification

### Why v3.3.0 Instead of v3.2.1?

1. **Breaking API Changes:** The transition affects public-facing type signatures:
   - `Address::script_hash()` changes return type from `ScriptHash` to `Option<ScriptHash>`
   - `Builder::public_keys_to_scripthash()` replaces panic behavior with `BuilderError` variants
   
2. **Semantic Versioning Compliance:** Removal of deprecated functionality warrants minor version increment when the deprecated API had been in use since v3.0.0 and migration requires explicit opt-in during transition period.

3. **Ecosystem Coordination:** Third-party integrators (exchange wallets, enterprise DApps) need clear signal that upgrading requires code review. A v3.2.x bugfix release would not convey sufficient urgency.

### Deprecation Timeline

| Deprecated API | Deprecation Version | Removal Target | Migration Path |
|---------------|--------------------|----------------|----------------|
| `Address::script_hash()` | v3.3.0 | v3.5.0 | Use `try_script_hash().unwrap_or_default()` |
| `Builder::public_keys_to_scripthash()` | v3.3.0 | v3.5.0 | Use `try_public_keys_to_scripthash()` |

*Note: Actual removal will occur after v3.4.0 maintenance window to provide ≥1 year migration grace period.*
