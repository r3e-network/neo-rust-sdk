# Neo Rust SDK v3.3.0 Implementation Plan

**Prepared By:** Felix (Coding Agent #98)  
**Date:** September 8, 2026  
**Target Release Date:** March 2027  
**Version Justification:** Minor version bump - introduces breaking changes in security-critical APIs

---

**Executive Summary**

v3.3.0 hardens Neo Rust SDK security infrastructure, completing SGX quote verification from v3.2.0 and addressing critical production gaps identified during fuzz testing and HD wallet regression analysis. Concurrently, this release tackles API inconsistencies discovered through property-based testing: introducing fallible conversion APIs with explicit error handling and comprehensive test coverage.

## Version Bump Justification

### Why v3.3.0 Instead of v3.2.1?

1. **Breaking API Changes:** Type signature modifications affect `Address::script_hash()` and `Builder::public_keys_to_scripthash()`

2. **Semantic Versioning Compliance:** Removal of deprecated functionality warrants minor version increment when migration requires explicit opt-in during transition period.

3. **Ecosystem Coordination:** Third-party integrators (exchange wallets, enterprise DApps) need clear signal that upgrading requires code review. A v3.2.x bugfix release would not convey sufficient urgency.

### Deprecation Timeline

| Deprecated API | Deprecation Version | Removal Target | Migration Path |
|---------------|--------------------|----------------|----------------|
| `Address::script_hash()` | v3.3.0 | v3.5.0 | Use `try_script_hash().unwrap_or_default()` |
| `Builder::public_keys_to_scripthash()` | v3.3.0 | v3.5.0 | Use `try_public_keys_to_scripthash()` |

*Note: Actual removal after v3.4.0 maintenance for ≥1 year migration grace period.*
